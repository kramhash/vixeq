# Migrating from 1.0.0-rc.1 to 1.0.0-rc.2: naming

- Status: Released in `1.0.0-rc.2`; see `CHANGELOG.md` "1.0.0-rc.2" →
  "Breaking"
- Audit: [`../reviews/rc2-api-audit-claude.md`](../reviews/rc2-api-audit-claude.md)
  (findings F13–F16)

The pre-1.0 API audit found three places where one concept had two names.
`1.0.0-rc.2` settles each on the name the rest of the API already used, so
these are renames: behavior does not change. TypeScript reports every call
site that needs an edit.

The other breaking changes in rc.2 are listed under "Breaking" in
`CHANGELOG.md`.

## Rename table

| rc.1 | rc.2 | Package |
| --- | --- | --- |
| `PlaybackTransport.seekMs()` | `seekPositionMs()` | `@vixeq/core` |
| `ArrangementEngine.getArrangement()` | `getProject()` | `@vixeq/core` |
| `ArrangementEngine.setArrangement()` | `setProject()` | `@vixeq/core` |
| `ArrangementProjectEvent.arrangement` / `previousArrangement` | `project` / `previousProject` | `@vixeq/core` |
| `useArrangement({ arrangement })` | `useArrangement({ project })` | `@vixeq/react` |
| `useSequencerEngine`, `useSequencePlayer` | `useSequencer` | `@vixeq/react` |
| `SequencerEngineHookOptions` | `UseSequencerOptions` | `@vixeq/react` |
| `SequencerEngineHookState`, `SequencePlayerHookState` | `UseSequencerState` | `@vixeq/react` |
| `SequencerEnginePendingOperation` | `SequencerPendingOperation` | `@vixeq/react` |
| `SequencerEngineLatestEvent` | `SequencerLatestEvent` | `@vixeq/react` |
| `MutableRefObject<T>` on `positionRef`, `latestEventRef`, and the `useAnimatedChannels` result | `ReadonlyRef<T>` | `@vixeq/react` |

## Transport seek (`seekMs` → `seekPositionMs`)

Every Engine, hook, and player ref already called this `seekPositionMs`; the
transport was the exception. A custom transport renames the method, and code
that seeks a transport directly renames the call.

```ts
// rc.1
const transport: PlaybackTransport = {
  // ...
  async seekMs(positionMs) { media.currentTime = positionMs / 1000; },
};
await transport.seekMs(1500);

// rc.2
const transport: PlaybackTransport = {
  // ...
  async seekPositionMs(positionMs) { media.currentTime = positionMs / 1000; },
};
await transport.seekPositionMs(1500);
```

## Arrangement uses "project"

Sequencer and Timeline already called the loaded data the project
(`getProject`, `setProject`, the `"project"` event, `useTimeline({ project })`).
Arrangement now does too. The pure helpers keep their names
(`createArrangement`, `normalizeArrangement`, `validateArrangement`, ...),
because they are named after the `ArrangementProject` type.

```tsx
// rc.1
engine.setArrangement(next);
engine.on("project", ({ arrangement, previousArrangement }) => { /* ... */ });
const player = useArrangement({ arrangement });

// rc.2
engine.setProject(next);
engine.on("project", ({ project, previousProject }) => { /* ... */ });
const player = useArrangement({ project: arrangement });
```

## `useSequencer`

The Sequencer hook had two names and its types followed a third pattern.
It is now `useSequencer`, with `UseSequencerOptions` and `UseSequencerState`
like `useArrangement` and `useTimeline`. `useSequencePlayer` and
`SequencePlayerHookState` were plain aliases and are removed.

```tsx
// rc.1
import { useSequencerEngine, type SequencerEngineHookState } from "@vixeq/react";
const state: SequencerEngineHookState = useSequencerEngine({ project });

// rc.2
import { useSequencer, type UseSequencerState } from "@vixeq/react";
const state: UseSequencerState = useSequencer({ project });
```

## Read-only refs (`ReadonlyRef<T>`)

`positionRef`, `latestEventRef`, and the ref that `useAnimatedChannels`
returns were typed `MutableRefObject<T>`, which `@types/react` 19 marks as
deprecated. React's `RefObject<T>` is not a replacement, because under
React 18 its `current` is `T | null`. The hooks now return
`ReadonlyRef<T> = { readonly current: T }`, exported from `@vixeq/react`.

Reading `current` works as before. The hooks own these refs, so assigning
to `current` is now a type error; keep your own `useRef` for values you
write.

```tsx
const { positionRef } = useSequencer({ project });
const positionMs = positionRef.current.positionMs; // unchanged

// A parameter typed MutableRefObject<ChannelPosition> no longer accepts it:
function readBeat(ref: ReadonlyRef<ChannelPosition>) {
  return ref.current.beat;
}
```
